## Воспроизведение результатов

### Окружение

Материалы рассчитаны на Linux x86-64 и GNU GCC/binutils. Результаты в отчётах получены с GCC 14.4.0; для лабораторной 2 также использовался GNU binutils 2.44. Версии инструментов, размеры файлов, адреса символов и отдельные строки диагностик в другом окружении могут отличаться.

На macOS и компьютерах с другой архитектурой удобнее запускать команды в контейнере `gcc:14` с платформой `linux/amd64`. Команды ниже выполняются из корня репозитория.

### Лабораторная 1, задача A

```sh
(
  cd Lab1/taskA
  docker run --rm --platform linux/amd64 \
    -v "$PWD":/w -w /w gcc:14 \
    sh run.sh > output.txt 2>&1
)
```

### Лабораторная 1, задача B

Читаемые программы собираются нативным C-компилятором. Последние две пары команд проверяют принятие правильного ввода и отклонение неправильного:

```sh
(
  cd Lab1/taskB
  cc -std=c99 -Wall -Wextra solve.c -o solve
  cc -std=c99 -Wall -Wextra restored.c -o restored

  ./solve legacy.c
  ./solve legacy.c | ./restored
  test "$?" -eq 0
  printf '%s\n' 'flag{wrong}' | ./restored
  test "$?" -eq 1
)
```

Для сборки исходного `legacy.c` на Linux нужны документированные совместимые настройки языка и увеличенный стек:

```sh
(
  cd Lab1/taskB
  ulimit -s unlimited
  gcc -std=gnu99 -Wno-implicit-int legacy.c -o legacy
)
```

Команда для Apple clang и объяснение ограничений приведены в [описании задачи B](Lab1/taskB/README.md#как-собрать-оригинальный-legacyc).

### Лабораторная 2

```sh
(
  cd Lab2
  docker run --rm --platform linux/amd64 \
    -v "$PWD":/w -w /w gcc:14 \
    sh run.sh > output.txt 2>&1
)
```

На этапе пересборки `hotfix.c` с `-fno-common` ожидается диагностическая ошибка `multiple definition of 'system_mode'`: это намеренная часть упражнения, после которой скрипт демонстрирует два исправления. Скрипты используют `set -x`, чтобы записать команды и их вывод в отчёт; это учебные сценарии воспроизведения, а не автоматические тесты.

## Состав репозитория

- Отчёты и ответы на вопросы находятся в файлах Markdown; исходные программы и решения — в файлах `.c` и `.cpp`.
- Файлы `.i` и `.s` сохранены для анализа этапов сборки в лабораторной 1, а `output.txt` — для проверки результатов выполнения команд.
- Четыре объектных файла `Lab2/{core,legacy,hotfix,main}.o` входят в исходный комплект лабораторной 2 и необходимы для её выполнения.

Повторный запуск сценариев может обновить сохранённый вывод команд. Получаемые исполняемые файлы и дополнительные объектные файлы исключены из Git через `.gitignore`.
