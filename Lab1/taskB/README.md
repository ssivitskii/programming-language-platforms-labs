# Лабораторная 1. Задача B — Наследие

## Флаг

```
flag{i_considered_giving_only_the_binary_24412707}
```

## Файлы

| файл | что это |
|---|---|
| `legacy.c` | исходный артефакт (без изменений) |
| `restored.c` | деобфусцированная, читаемая и компилируемая без лишних флагов версия той же программы |
| `solve.c` | программа, извлекающая флаг прямо из `legacy.c` |

## Проверка

```bash
cc -std=c99 -Wall -Wextra solve.c -o solve
cc -std=c99 -Wall -Wextra restored.c -o restored
./solve legacy.c                      # печатает флаг
./solve legacy.c | ./restored; echo $?   # 0 — флаг принят
echo 'flag{wrong}' | ./restored; echo $? # 1 — отклонён
```

Оригинал тоже принимает этот флаг (exit 0) и отклоняет другие строки (exit 1). Проверено и на macOS (Apple clang 17), и на Linux x86-64 (GCC 14.4).

## Как собрать оригинальный `legacy.c`

Как есть он не компилируется современными компиляторами. В нём три «ловушки»:

1. **`register n = 128;` без типа** — неявный `int` из C89. В C99+ это ошибка (`-Wimplicit-int` по умолчанию error в GCC 14 и clang 16+).
2. **`for (int i = 0; ...)`** — объявление в `for`, доступное только с C99. Поэтому просто `-std=c89` не помогает: нужен C99 с разрешённым неявным `int`.
3. **Вложенность `z(z(z(...)))` до 6765 уровней.** Clang по умолчанию ограничивает вложенность скобок 256 уровнями, а рекурсивный парсер и GCC, и clang переполняет стек и падает (`Segmentation fault` / `Illegal instruction`).

Рабочие команды:

```bash
# Linux, GCC
ulimit -s unlimited
gcc -std=gnu99 -Wno-implicit-int legacy.c -o legacy

# macOS, Apple clang
ulimit -s 65520
clang -std=gnu89 -w -fbracket-depth=8192 legacy.c -o legacy
```

(В Docker с эмуляцией amd64 через QEMU ещё нужен `-e QEMU_STACK_SIZE=1073741824`, иначе `ulimit` не действует на стек эмулируемого процесса.)

## Разбор

После раскрытия макросов (`A`=`static`, `B`=`malloc`, `E(x)`=`return x`, `P(x,y)`=`x y`, `T(x,y)`=`x##y`, `U(x,y)`=`x` …) программа выглядит так:

```c
struct s { struct s *s; };

static struct s *z(struct s *n)          /* добавить узел в начало списка */
{ struct s *t = n; n = malloc(sizeof(struct s)); n->s = t; return n; }

static int pi(struct s *n)               /* длина списка (не используется) */
static struct s *ip(int n)               /* построить список длины n (n<=0 — пустой) */
static int pc(struct s *n, struct s *o)  /* 1, если длины списков различаются */

static void df(int *p);                  /* преобразование — Duff's device */
static void dc(int *d, char *s);         /* копирование 1024 char -> int — Duff's device */
static int  ch(int *n);                  /* сравнение с эталоном */

int main(void)
{
    static char b[1024]; static int i[1024];
    fgets(b, 1024, stdin);
    dc(i, b);
    df(i);
    return !ch(i);          /* 23 восклицательных знака подряд == одно отрицание */
}
```

### Числа Пеано

Эталон в `ch()` — массив `struct s *a[1024]`, где каждое число записано **в унарной системе** как связный список: `z(z(z(0)))` — список из трёх узлов, т.е. 3. `ip(n[i])` строит такой же список из введённого значения, `pc()` сравнивает длины. Отсюда и 280 КБ скобок. Значит, ожидаемое значение элемента = число вызовов `z(` в нём.

### Преобразование `df()` — сломанный Duff's device

```c
register n = 128;
switch (1024 % 8) {            /* = 0 */
case 0: do { *p ^= 0x63; p++;
case 7:      *p ^= 48;   p++;
case 6:
case 5:      *p <<= 4;   p++;  /* у case 6 нет своего тела и p++ */
case 4:      *p <<= 2;   p++;
case 3:      *p *= 55;   p++;
case 2:      *p -= -97;  p++;  /* т.е. += 97 */
case 1:      *p += 44;   p++;
        } while (--n > 0);
}
```

Похоже на классический Duff's device на 8, но `case 6:` и `case 5:` склеены. За итерацию обрабатываются **7** элементов, всего 128 × 7 = **896**, а элементы 896–1023 не меняются. Операция зависит от `i % 7`:

| `i % 7` | прямая | обратная |
|---|---|---|
| 0 | `^= 0x63` | `^= 0x63` |
| 1 | `^= 48` | `^= 48` |
| 2 | `<<= 4` | `>>= 4` |
| 3 | `<<= 2` | `>>= 2` |
| 4 | `*= 55` | `/= 55` |
| 5 | `+= 97` | `-= 97` |
| 6 | `+= 44` | `-= 44` |

### Решение

`solve.c` находит в `legacy.c` инициализатор `S*a[1024]={...}`, удаляет пробельные символы (`z` и `(` иногда стоят на разных строках), считает `z(` в каждом элементе верхнего уровня и применяет обратные операции. Первые элементы:

```
ожидается: 5    92   1552  412  6765  ...
обратное:  5^0x63=102 'f', 92^48=108 'l', 1552>>4=97 'a', 412>>2=103 'g', 6765/55=123 '{' ...
```

Получается `flag{i_considered_giving_only_the_binary_24412707}\n`, дальше нули: `fgets` оставляет `\n`, а остаток статического буфера нулевой. Нулевые элементы после преобразования дают `99, 48, 0, 0, 0, 97, 44`. Именно этот повторяющийся узор `…,0,0,0,…` виден в хвосте массива.
